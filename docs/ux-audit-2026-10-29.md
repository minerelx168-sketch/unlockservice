# Storefront UX audit — 29 October 2026

## Evidence and scope

Reviewed the live iUnlockMobile home, service-selection workflow and Apple Free Check with the public UnlockRiver homepage as a visual reference. The earlier display audit covered 24 desktop routes and 14 routes at a 390px mobile width; those observations predate this change. Source review covers shared typography, controls, responsive storefront styles and motion.

The current cloud browser supports desktop observation but exposes no viewport resize capability. The responsive refinements below have been reviewed in source; they still require post-deployment visual checks on real mobile/tablet widths and text zoom. No real checkout, Provider order or customer data was used for this UI audit.

## Findings and changes

- Headlines: tight tracking, especially Apple Free Check at -0.055em, made letter shapes crowd. Relax tracking and increase heading leading.
- Mobile labels: shortcut captions were 9px, with several important quote/help labels at 10–11px. Use at least 12px for compact storefront labels, 13px for quote labels/input guidance and preserve 16px inputs. At 420px and below, quick picks become full-width readable rows.
- Quote card: Card total and the under-$1 account note touched the edge. Give both the same inset as the service price and delivery estimate.
- Next action: an unselected form said Preview and then returned an error. Its first action now says Choose a service and opens the existing searchable selector. After selection the existing preview and payment flow remains.
- Examples: the shared selector supports approved examples, but the home and two main service-page projections omitted hasExample. Pass that catalog flag through without inventing examples for unsupported services.
- Touch and keyboard: mobile header icons are 44px; the main order action is 54px. Service-list focus outlines are inset so the scroll container cannot clip them. Selected options retain their text state and gain an edge marker.
- Motion: borrow the reference's soft depth and clear form emphasis. Keep a static gradient, short form/FAQ feedback, a desktop-only button sheen and subtle icon movement. Remove continuously looping decoration; shorten scroll reveals and preserve reduced-motion and no-JavaScript access.
- Navigation: retain the desktop drawer because it exposes the complete service tree, in addition to the primary navigation links.

No prices, provider mappings, payment settings, eligibility rules, analytics or catalog availability change. Examples remain explicitly identified as examples and cannot be mistaken for a paid device result.

## Release checks

Run repository lint, TypeScript checks, unit suite and production build. After deploy, verify:
1. Home, Unlock, Phone Check and Apple Free Check at 320, 390, 768, 1024 and 1440px, plus 200% text zoom.
2. Choose a service opens the picker, search Enter does not submit, Escape closes, and a selected service shows its existing real retail price.
3. Reviewed examples appear only where hasExample is true; selecting and reviewing never calls the paid Provider API.
4. Invalid details keep existing validation; valid details open the existing preview. Do not submit paid orders during UI-only QA.
5. Keyboard focus remains visible and reduced-motion disables all added effects.
6. The admin Apple Free Check fix from PR #28 remains present; validate using a permitted account without consuming a Provider check unless separately requested.

Production deployment is not recorded as complete here. Manus Cloud Computer currently requires authentication, and the cloud browser's authentication security check was unavailable.
