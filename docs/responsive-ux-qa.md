# Responsive UX/UI review — 7 September 2026

ปรับหน้าสำหรับลูกค้าตั้งแต่เลือกบริการ เข้าสู่ระบบ ซื้อรายงาน เติมเงิน ไปจนถึงติดตามผล โดยคงสีและฟอนต์หลักเดิม
การตรวจใช้ production build บน localhost, browser ใน Codex และฐานข้อมูลจำลองแยกจาก production

## สิ่งที่พบและแก้ไข

## พฤติกรรมที่ตรวจด้วย browser

- ข้อมูลจำลองมีชื่อบริการยาว, ผลรายงานยาว, โค้ดปลดล็อกยาว และหลายสถานะ เพื่อทดสอบกรณีเนื้อหายาว
- ช่องกรอกและ select ที่เห็นในฟอร์มใช้ขนาดอย่างน้อย 16px ในการตั้งค่ามาตรฐานที่ทดสอบ
- Filters เปิด/ปิดได้, ค่าที่เลือกยังแสดงเมื่อย่อ, Reset ล้างค่าได้ และเลือก Apple Basic หลังค้นหา Samsung ได้ผลลัพธ์เดียวตามที่เลือก
- ปุ่มซื้อในการ์ดและปุ่มยืนยัน/กลับไปแก้ใน Review สูง 48px ตามค่าที่อ่านจาก DOM
- หน้า checkout ไม่กาง picker โดยอัตโนมัติ; กรอก IMEI ผิดแล้ว focus กลับช่องที่ผิดพร้อม aria-invalid; กรอกถูกแล้วเข้า Review ได้
- Escape ปิดเมนูบัญชีและคืน focus ให้ปุ่ม Menu; dropdown จอแนวนอนเลื่อนถึงรายการท้ายได้
- ตรวจภาพจริงของ mobile catalog, ประวัติรายงาน และ checkout แบบ dark เพิ่มจากค่าความกว้างใน DOM

## การตรวจโค้ด

- `npm run lint`, `npm run typecheck`, `npm run build` ผ่าน
- 35/35 tests ผ่านด้วย `node --import tsx --test tests/*.test.ts`; ใช้ runner นี้เพราะ sandbox จำกัด IPC ของ wrapper `npm test`
- `git diff --check` ผ่าน
- ถอนเฉพาะ assertion เดิม 2 จุดที่ตรึง padding 20px และปุ่ม 46px; การปรับเป็น fluid padding/ปุ่มใหญ่ขึ้นตรวจจาก browser โดยตรง ส่วนการทดสอบ routing, availability, payment และ provider behavior ยังคงอยู่

ไม่มีการเปลี่ยนข้อกำหนดการชำระเงินหรือการคิดเครดิตในรอบนี้; ไม่มีขั้นต่ำเติมเงินและ Contact us จากรอบก่อนยังคงอยู่
ยังไม่ได้ merge/deploy หรือทดสอบอุปกรณ์จริงทุกยี่ห้อ, browser ทุกเวอร์ชัน, screen reader ทั้งระบบ และการชำระเงินจริง จึงไม่อ้างว่าเป็นการรับรอง accessibility หรือวัด conversion uplift แล้ว
Browser ที่ไม่รองรับ container queries จะใช้ตารางเลื่อนภายใน wrapper ตามรูปแบบสำรองเดิม
